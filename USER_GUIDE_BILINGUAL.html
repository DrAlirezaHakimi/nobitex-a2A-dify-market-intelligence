۱. نصب و اجرای پروژه در Windows

این مسیر برای Windows 10/11 و اجرای مستقیم با CMD مناسب است.

1. Install and run on Windows

Use this path for Windows 10/11 and direct execution from CMD.

1
استخراج پروژهExtract the project

ZIP را با Extract All در مسیری مانند `C:\Projects\Nobitex_A2A` استخراج کنید. فایل BAT را از داخل پنجره ZIP اجرا نکنید.

Extract the ZIP to a folder such as `C:\Projects\Nobitex_A2A`. Do not run the BAT file from inside the ZIP preview.

2
بررسی نصب PythonVerify Python

CMD را باز کنید و این دو دستور را اجرا کنید. باید نسخه 3.12 یا بالاتر نمایش داده شود.

Open CMD and run these commands. The version should be 3.12 or newer.

py --version py -m pip --version

اگر `py` شناخته نشد، Python را از وب‌سایت رسمی نصب کنید و هنگام نصب گزینه Python Launcher و Add Python to PATH را فعال کنید؛ سپس CMD را ببندید و دوباره باز کنید.

If `py` is not recognized, install Python from the official website, enable Python Launcher and Add Python to PATH, then reopen CMD.

python.org/downloads

3
اجرای فایل شروعRun the startup script

وارد پوشه اصلی پروژه شوید و روی `start_windows.bat` دوبار کلیک کنید؛ یا از CMD همان فایل را اجرا کنید. اسکریپت وابستگی‌ها را نصب می‌کند، در صورت نبودن `.env` یک کلید تصادفی امن می‌سازد و دو سرویس را اجرا می‌کند. پنجره CMD را باز نگه دارید.

Open the project folder and double-click `start_windows.bat`, or run it from CMD. It installs dependencies, creates a strong random API key in `.env` if missing, and starts both services. Keep the CMD window open.

cd /d C:\Projects\Nobitex_A2A start_windows.bat
4
باز کردن داشبوردOpen the dashboard

در مرورگر این آدرس را باز کنید:

Open this address in your browser:

http://127.0.0.1:8001

برای بررسی سلامت Backend نیز می‌توانید این آدرس را باز کنید؛ باید یک پاسخ JSON با `ok: true` دریافت کنید:

To verify backend health, open this URL. It should return JSON containing `ok: true`:

http://127.0.0.1:8000/health
5
شناخت حالت Demo و LiveUnderstand Demo and Live modes

حالت پیش‌فرض `MARKET_MODE=demo` است و داده‌ها ساختگی و برچسب‌خورده‌اند. برای داده عمومی نوبیتکس، فایل `.env` را با Notepad باز کنید، مقدار را به `MARKET_MODE=live` تغییر دهید، ذخیره کنید و با `Ctrl+C` سرویس را متوقف و دوباره `start_windows.bat` را اجرا کنید.

The default is `MARKET_MODE=demo`; values are synthetic and labelled. To read public Nobitex data, open `.env` in Notepad, change it to `MARKET_MODE=live`, save, stop the app with `Ctrl+C`, and run `start_windows.bat` again.

MARKET_MODE=demo
در حالت LIVE نیز فقط داده عمومی بازار خوانده می‌شود؛ ورود به حساب صرافی و ثبت سفارش واقعی در این پروژه پیاده‌سازی نشده است.
LIVE mode still reads public market data only. Exchange account login and real order placement are not implemented.

۳. اتصال پروژه به Dify Cloud

این قسمت را پس از آن انجام دهید که اجرای مستقیم داشبورد روی رایانه شما موفق شده باشد.

3. Connect the project to Dify Cloud

Complete this section only after the direct local dashboard scan works.

مهم: سه کلید متفاوت وجود دارد. آن‌ها را با هم اشتباه نگیرید و هیچ‌کدام را در GitHub، اسکرین‌شات یا پیام عمومی قرار ندهید.
Important: there are three different keys. Do not mix them up or place any of them in GitHub, screenshots, or public messages.
نام کلیدKeyمحل / کاربردWhere / purpose
API_KEYدر فایل `.env` محلی؛ از Backend محافظت می‌کند.In local `.env`; protects the A2A backend.

1
اجرای Backend و راه‌اندازی ngrokStart the backend and ngrok

ابتدا برنامه محلی باید روشن باشد. سپس در CMD دوم اجرا کنید:

Keep the local app running. In a second CMD window, run:

ngrok http 8000

آدرس HTTPS مقابل Forwarding را بردارید؛ مثلاً `https://your-name.ngrok-free.dev`. فقط همین دامنه را بدون مسیر و بدون اسلش انتهایی استفاده کنید. در مرورگر، افزودن `/health` باید JSON سلامت Backend را نشان دهد.

Copy the HTTPS Forwarding address, for example `https://your-name.ngrok-free.dev`. Use the base domain only, with no path and no trailing slash. Open it with `/health` to verify the backend.

اگر خطای `ERR_NGROK_334` و پیام endpoint already online دیدید، همان تونل فعال قبلی را استفاده کنید یا پنجره ngrok قبلی را با Ctrl+C ببندید؛ برای یک دامنه ثابت دو تونل هم‌زمان نسازید.
If you see `ERR_NGROK_334` / endpoint already online, reuse the existing tunnel or stop the previous ngrok process with Ctrl+C. Do not start two simultaneous tunnels for the same reserved domain.
2
Import کردن Workflow پایهImport the base workflow

در Dify Studio یک Workflow بسازید و فایل `dify/Hakimi_Nobitex_A2A_Gateway.yaml` را با گزینه Import DSL وارد کنید. در ورودی‌های Start، مقدار `backend_url` را برابر دامنه HTTPS فعال ngrok و `top_k` را مثلاً 15 قرار دهید.

In Dify Studio, create a Workflow and import `dify/Hakimi_Nobitex_A2A_Gateway.yaml` using Import DSL. In the Start inputs, set `backend_url` to the active HTTPS ngrok base URL and `top_k` to a value such as 15.

3
ساخت Secret با نام A2A_API_KEYCreate the A2A_API_KEY Secret

در ویرایشگر Workflow روی دکمه `ENV` در نوار بالای صفحه کلیک کنید. یک Environment Variable جدید با نام دقیق `A2A_API_KEY` بسازید و نوع آن را `Secret` انتخاب کنید. مقدار آن باید همان مقدار `API_KEY` در فایل `.env` باشد. کلید را از `.env` محلی بردارید؛ آن را در چت یا فایل YAML نگذارید.

In the Workflow editor, click `ENV` in the top toolbar. Add an Environment Variable named exactly `A2A_API_KEY` and choose type `Secret`. Its value must match `API_KEY` in the local `.env` file. Copy it locally from `.env`; never paste it into chat or the YAML file.

اگر در فهرست متغیرهای نود HTTP ظاهر نشد، ابتدا Secret را در ENV ذخیره کنید، پنجره تنظیمات نود را ببندید و دوباره باز کنید یا صفحه را Refresh کنید.

If it does not appear in the HTTP node variable picker, save the Secret first, close and reopen the node settings, or refresh the editor.

4
تنظیم Header در نود HTTP RequestConfigure the HTTP Request header

در نود HTTP Request یک Header با Key برابر `X-API-Key` اضافه کنید و Value را از متغیر محرمانه `A2A_API_KEY` انتخاب کنید. مطمئن شوید URL نود به دامنه HTTPS و مسیر `/api/scan` ختم می‌شود. تنظیمات را ذخیره کنید.

In the HTTP Request node, add a header with key `X-API-Key` and choose the secret variable `A2A_API_KEY` as its value. Verify that the node URL uses the HTTPS domain and ends with `/api/scan`. Save the node.

Header name: X-API-Key Header value: A2A_API_KEY (Secret) Method: GET URL: {{backend_url}}/api/scan?top_k={{top_k}}
5
Test Run و PublishTest Run and publish

ابتدا Test Run بگیرید و `backend_url` و `top_k` را وارد کنید. در صورت موفقیت، Workflow را Publish کنید. تغییر Secret یا Header را نیز پس از ذخیره، دوباره Publish کنید.

Run a Test Run with `backend_url` and `top_k`. If it succeeds, Publish the Workflow. Republish after changing the Secret or header.

6
اتصال دکمه «اجرای تحلیل از Dify» در داشبورد محلیEnable the dashboard's “Run through Dify” button

در Dify به Access Point اپلیکیشن بروید و از API Key یک Service API Key بسازید. کلید را در فایل `.env` محلی در مقدار `DIFY_API_KEY` قرار دهید. سپس `PUBLIC_BASE_URL` را برابر دامنه HTTPS فعال ngrok بگذارید. `DIFY_API_BASE` برای Dify Cloud همان مقدار پیش‌فرض زیر است.

Open the app's Access Point in Dify and create a Service API key under API Key. Put it in the local `.env` as `DIFY_API_KEY`. Set `PUBLIC_BASE_URL` to the active HTTPS ngrok base URL. For Dify Cloud, keep the default `DIFY_API_BASE` shown below.

PUBLIC_BASE_URL=https://your-active-domain.ngrok-free.dev DIFY_API_KEY=your-dify-app-service-api-key DIFY_API_BASE=https://api.dify.ai/v1

کلیدی که در Access Point ساخته‌اید، برای `DIFY_API_KEY` است؛ آن را به‌جای `A2A_API_KEY` در Header نود HTTP قرار ندهید. پس از ذخیره `.env`، برنامه را با Ctrl+C متوقف و دوباره اجرا کنید. داشبورد باید وضعیت Dify را آماده نشان دهد.

The Access Point key belongs in `DIFY_API_KEY`; do not use it as `A2A_API_KEY` in the HTTP header. Save `.env`, stop the app with Ctrl+C, and restart it. The dashboard should show Dify as ready.

در نهایت، دو مسیر مستقل دارید: «اسکن مستقیم A2A» برای اجرای محلی و «اجرای تحلیل از Dify» برای اجرای Workflow منتشرشده از طریق Dify Cloud.
You now have two independent paths: “Direct A2A Scan” for local execution and “Run through Dify” for the published Dify Cloud workflow.

۴. فعال‌سازی Workflow اختیاری LLM

این نسخه، Workflow پایه را تغییر نمی‌دهد؛ یک Workflow جداگانه برای توضیح متنی خروجی می‌سازد.

4. Enable the optional LLM workflow

This does not replace the base workflow. It is a separate workflow that adds a natural-language explanation.

1

فایل `dify/Hakimi_A2A_Optional_LLM_Explainer.yaml` را به‌عنوان یک Workflow جدید Import کنید.

Import `dify/Hakimi_A2A_Optional_LLM_Explainer.yaml` as a new Workflow.

2

مانند Workflow پایه، `backend_url`، متغیر Secret به نام `A2A_API_KEY` و Header `X-API-Key` را تنظیم کنید.

As with the base workflow, configure `backend_url`, the `A2A_API_KEY` Secret, and the `X-API-Key` header.

3

در نود LLM یک Provider و مدل فعال در حساب Dify خود انتخاب کنید. نام مدل داخل YAML صرفاً نمونه است و ممکن است لازم باشد Provider یا تنظیمات Schema را متناسب با حساب خود اصلاح کنید.

In the LLM node, select a provider and model enabled in your Dify workspace. The model name in the YAML is only an example; provider or schema settings may need adjustment for your account.

4

Test Run و سپس Publish انجام دهید. اگر می‌خواهید دکمه داشبورد محلی همین Workflow را اجرا کند، API Key مربوط به همین اپلیکیشن را از Access Point بردارید و در `DIFY_API_KEY` بگذارید؛ سپس برنامه را Restart کنید.

Test Run and then Publish. If the local dashboard should call this workflow, create an API key for this specific app in Access Point, put it in `DIFY_API_KEY`, and restart the local application.

نقش LLM فقط توضیح زبانیِ محافظه‌کارانه است. محاسبات عددی و امتیازها در Python تولید می‌شوند؛ LLM نباید قیمت، امتیاز یا تصمیم عددی را تغییر دهد. سازگاری YAML اختیاری با همه Providerها تضمین نشده است.
The LLM is only a cautious explanatory layer. Numeric calculations and scores are produced by Python; the LLM should not change prices, scores, or numeric decisions. The optional YAML is not guaranteed to work unchanged with every provider.

۵. اجرای اختیاری با Docker

برای Docker Desktop یا Docker Engine به همراه Compose مناسب است.

5. Optional Docker deployment

Use Docker Desktop or Docker Engine with Compose.

ابتدا `.env` را ایجاد کنید. ساده‌ترین روش، یک بار اجرای `start_windows.bat` برای ساخت فایل و کلید است؛ سپس برنامه را متوقف کنید. مطمئن شوید `API_KEY` حداقل ۲۴ کاراکتر و تصادفی است.

Create `.env` first. One easy method is to run `start_windows.bat` once to generate the file and key, then stop the app. Ensure `API_KEY` is random and at least 24 characters.

docker compose up --build -d docker compose logs -f docker compose down
Docker و اجرای مستقیم ویندوز را هم‌زمان روی همین پورت‌ها اجرا نکنید. Compose فقط `127.0.0.1:8000` و `127.0.0.1:8001` را روی میزبان منتشر می‌کند.
Do not run Docker and the native Windows app simultaneously on the same ports. Compose binds only `127.0.0.1:8000` and `127.0.0.1:8001` on the host.

۷. امنیت، محدودیت‌ها و مسئولیت استفاده

7. Security, limitations, and responsible use

  • فایل `.env` محرمانه است و نباید در GitHub یا برای دیگران ارسال شود. این فایل در `.gitignore` مستثنا شده است؛ بااین‌حال پیش از انتشار، وضعیت مخزن را بررسی کنید.
  • فقط Backend روی پورت 8000 را در صورت نیاز از طریق HTTPS در دسترس Dify قرار دهید. پورت 8001 داشبورد خصوصی است و نباید تونل یا عمومی شود.
  • اگر کلیدی افشا شد، آن را فوراً در محل مربوطه عوض کنید و برنامه/Workflow را با کلید جدید به‌روزرسانی کنید.
  • در LIVE فقط داده عمومی بازار خوانده می‌شود؛ ورود به حساب کاربری، کیف پول، ثبت سفارش، معاملات تعهدی و فروش استقراضی وجود ندارد.
  • امتیازها رتبه‌بندی‌های ابتکاری و کالیبره‌نشده‌اند، نه احتمال سود. این نسخه بک‌تست OHLC، شبیه‌سازی Fill یا تضمین بازده ندارد.
  • پیاده‌سازی A2A یک زیرمجموعه JSON-RPC است و ادعای انطباق کامل با SDK/استاندارد جاری A2A ندارد.
  • The `.env` file is private. Never commit or share it. It is excluded by `.gitignore`, but still inspect repository contents before publishing.
  • Expose only backend port 8000 to Dify over HTTPS when needed. Port 8001 is the private dashboard and must never be tunneled or made public.
  • If a key is exposed, rotate it immediately in the relevant service and update the app/workflow.
  • LIVE mode reads public market data only. Account login, wallets, order placement, margin, and short selling are not implemented.
  • Scores are uncalibrated heuristic rankings, not probabilities of profit. This release has no OHLC backtest, fill simulation, or return guarantee.
  • The A2A implementation is a JSON-RPC subset and is not claimed to be fully compliant with the current A2A SDK/specification.
