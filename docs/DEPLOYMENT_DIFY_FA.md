# Nobitex A2A × Dify — سامانه یکپارچه پایش بازار

**نسخه 1.0 | ۳ نوامبر ۲۰۲۶ | تهیه‌شده برای [دکتر علیرضا حکیمی](https://alirezahakimi.ir)**

این بسته، توسعه همان پروژه قبلی است؛ داشبورد جدید به جای نمایش خودکار داده‌های نمونه، از سرور محلی **داده واقعی عمومی نوبیتکس** دریافت می‌کند و می‌تواند اجرای Workflow منتشرشده Dify Cloud را نیز از طریق سرور واسط درخواست کند. **هیچ سفارش واقعی اجرا نمی‌شود.** هدف، ارزیابی واقعی *مسیر داده و معماری* است نه تضمین سودآوری استراتژی.

## ۱. چه چیزی واقعی شده است؟

- دریافت اردربوک تمام نمادهای قابل‌پشتیبانی از `GET https://apiv2.nobitex.ir/v3/orderbook/all` و آمار بازار از `/market/stats`، بدون کلید معاملاتی.
- تحلیل چندعاملی مبتنی بر HTTP/JSON-RPC (زیرمجموعه A2A نسخه 0.2.6) با کنترل کیفیت داده، اسپرد، حجم، مدیریت اندازه موقعیت و مقایسه نتایج.
- داشبورد جدید در `http://127.0.0.1:8001` با دو دکمه: «اسکن مستقیم A2A» و «اجرای تحلیل از Dify».
- اتصال **واقعی Server-to-Server** از داشبورد به Dify Cloud API (`POST /v1/workflows/run`) و سپس از Dify به موتور A2A از طریق دامنه HTTPS فعال ngrok.
- ذخیره سوابق در SQLite محلی؛ هر رکورد با منبع اجرا (`DIFY_WORKFLOW` یا `A2A_DIRECT`) و زمان ثبت می‌شود.
- کلیدهای Dify و A2A فقط در `.env` محلی؛ در فایل HTML و درخواست‌های مرورگر نیستند.
- شکست شفاف در صورت خطای شبکه/401/خروجی ناقص/داده کهنه؛ در حالت `live` هرگز داده مصنوعی جایگزین نمی‌شود.

## ۲. راه‌اندازی مرحله به مرحله روی ویندوز

**مرحله ۱.** فایل ZIP را در پوشه جدید Extract کنید. CMD قبلی Python را با Ctrl+C ببندید تا پورت 8000 آزاد شود؛ ngrok را می‌توانید باز بگذارید. اگر اولین اجراست، فایل `start_windows.bat` را اجرا کنید؛ وابستگی‌ها نصب و فایل `.env` به‌صورت خودکار با کلید تصادفی قوی ساخته می‌شود. حالت پیش‌فرض `MARKET_MODE=live` است.

**مرحله ۲.** مرورگر را باز کنید: **http://127.0.0.1:8001**. اکنون «اسکن مستقیم A2A» باید به موتور محلی روی پورت 8000 وصل شود. اگر به نوبیتکس در شبکه شما دسترسی وجود نداشته باشد، خطا می‌بینید؛ این نسخه داده ساختگی را به جای واقعی نمایش نمی‌دهد.

**مرحله ۳.** برای مسیر Dify، ابتدا Dify Workflow که قبلاً در Dify Cloud ساخته‌اید را از حالت `Unpublished` خارج کنید: `Studio → Workflow → Publish`. سپس از `Access Point` / `API Access` / `API Keys` (بسته به نسخه رابط کاربری) یک **Service API Key مختص همان Workflow** بسازید. این کلید با کلید `A2A_API_KEY` داخل ENV دیفای فرق دارد.

**مرحله ۴.** فایل `.env` را با Notepad باز کنید. فقط در سیستم خودتان آن را ویرایش کنید؛ **به هیچ‌کس نفرستید**:

```ini
MARKET_MODE=live
API_KEY=<random-secret-generated-on-first-start>
PUBLIC_BASE_URL=https://your-active-ngrok-domain.ngrok-free.dev
DIFY_API_KEY=<Dify-Workflow-Service-API-Key>
DIFY_API_BASE=https://api.dify.ai/v1
```

کادر `PUBLIC_BASE_URL` باید دقیقاً دامنه *فعال ngrok* باشد که به **پورت 8000** تونل شده است. `/health` و `/api/scan` به آخر آن اضافه نکنید. `DIFY_API_KEY` را از بخش دسترسی API اپلیکیشن Dify بگیرید؛ نه از ENV داخلی Workflow.

**مرحله ۵.** در خود Dify، در بخش ENV متغیر `A2A_API_KEY` باید دقیقاً با `API_KEY` فایل `.env` جدید برابر باشد. نود HTTP Request هدر `X-API-Key` را از آن ENV بخواند. سپس `Publish` را بزنید. پس از راه‌اندازی ngrok با `ngrok http 8000`، از آدرس تونل `/health` را آزمایش کنید. اگر Dify ENV را تغییر دادید، باید تغییرات Dify را نیز انتشار دهید.

**مرحله ۶.** برنامه Python را با Ctrl+C متوقف و `start_windows.bat` را دوباره اجرا کنید تا `.env` جدید خوانده شود. در داشبورد `http://127.0.0.1:8001` باید برچسب Dify «آماده» باشد. روی **اجرای تحلیل از Dify** کلیک کنید. اجرای موفق، شناسه اجرای Dify، گزارش متنی و اطلاعات عامل‌ها را روی همان HTML برمی‌گرداند. اگر `404` دیدید Workflow منتشر نشده؛ اگر `401` دیدید DIFY_API_KEY یا متغیر A2A_API_KEY مشکل دارد.

**مرحله ۷.** برای تشخیص خطا، فایل `run_diagnostics_windows.bat` را اجرا کنید. این اسکریپت هیچ کلیدی چاپ نمی‌کند. با `Ctrl+C` برنامه را متوقف کنید.

## ۳. معماری

```text
Chrome → http://127.0.0.1:8001 (داشبورد محلی)
       → FastAPI UI Gateway :8001 [کلیدها در سرور]
                ├─ اسکن مستقیم → FastAPI A2A :8000 → داده عمومی Nobitex
                └─ تحلیل از Dify → https://api.dify.ai/v1/workflows/run
                                    → Dify Published Workflow
                                    → HTTPS ngrok → FastAPI A2A :8000
                                    → خروجی JSON + گزارش به UI Gateway → Chrome
```

**هشدار مهم:** فقط پورت **8000** به ngrok وصل شود؛ پورت **8001** مخصوص داشبورد محلی است و نباید تونل عمومی دریافت کند. از مسیر `http://127.0.0.1:8000/` دیگر داشبورد قدیمی نمایش داده نمی‌شود؛ آن پورت صرفاً Backend است. داشبورد جدید را روی **8001** باز کنید.

## ۴. حالت DEMO و LIVE

- `MARKET_MODE=demo`: داده‌ها تماماً ساختگی و صرفاً برای آزمون مسیر ارتباط هستند.
- `MARKET_MODE=live`: داده عمومی زنده صرافی، **نه سفارش واقعی و نه داده لحظه‌به‌لحظه WebSocket**. فرکانس دریافت توسط `MARKET_TTL` محدود شده است؛ پیش‌فرض ۷۰ ثانیه. نقدشوندگی، تاخیر، کارمزد و بازار بسته فیلتر می‌شوند. داده نامعتبر و خارج از زمان پذیرفته نمی‌شود. هیچ fallback ساختگی وجود ندارد.
- اگر اردربوک یا `/market/stats` در شبکه شما قابل‌دریافت نباشد، به جای سیگنال کاذب خطا نمایش داده می‌شود.

## ۵. مرز کارکرد، محدودیت‌ها و عدم تضمین

- امتیاز BUY/SELL یک **امتیاز رتبه‌بندی قانون‌محور** است؛ دقت پیش‌بینی یا احتمال سود ۵۱٪ نیست. تصمیم فروش فقط برای دارایی اسپات موجود معنا دارد.
- A2A فعلی **زیرمجموعه‌ای از قرارداد JSON-RPC Agent-to-Agent** است و آزمون انطباق کامل با SDK استاندارد A2A انجام نشده. عامل‌ها مستقلِ مبتنی بر مدل زبانی نیستند؛ تحلیل عددی آن‌ها در Python قطعی انجام می‌شود.
- Dify فعلاً Workflow orchestrator/report است و **LLM مستقل در Workflow موجود اجباری نیست**. افزودن LLM توضیح‌دهنده جداگانه نیازمند فعال‌کردن مدل و گاردریل است.
- معامله واقعی، احراز هویت حساب نوبیتکس، معاملات تعهدی، لغزش واقعی سفارش، بک‌تست چنددوره‌ای و ردیابی پرتفوی در این نسخه وجود ندارد.
- لازم است واحد پول **IRT/RLS**، کارمزد واقعی و حداقل اندازه سفارش مطابق API زنده و مشخصات حساب شما بررسی شود؛ قیمت‌های مرجع را مبنای سفارش واقعی قرار ندهید.
- ذخیره سوابق SQLite صرفاً metadata اجرای اسکن را دارد، نه کل خروجی تاریخی بازار؛ بنابراین خودبه‌خود برای بک‌تست کافی نیست.

`tests` شامل آزمون‌های اعتبارسنجی API، کیفیت داده، ارتباط A2A، رد داده ساختگی در حالت Live، بررسی تاریخ داده، عملیات درگاه Dify با Mock، حفاظت Origin و عدم نمایش کلید در HTML است. **این آزمون‌ها جای تست Live در شبکه شما، بارسنجی یا بک‌تست معاملاتی را نمی‌گیرند.**

## ۸. اجرای Docker (اختیاری)

برای Docker، پس از ساخت `.env` با کلید قوی (می‌توانید یک بار `start_windows.bat` را اجرا کنید تا `.env` ساخته شود)، در پوشه پروژه اجرا کنید:

```bash
docker compose up --build -d
```

این Compose فقط پورت‌های **127.0.0.1:8000** و **127.0.0.1:8001** را روی میزبان منتشر می‌کند؛ `.env` در image قرار نمی‌گیرد و پایگاه سوابق داخل `./data` ذخیره می‌شود. ویندوز و Docker را **هم‌زمان روی همین پورت‌ها اجرا نکنید**. برای آزمایش دمو مقدار `MARKET_MODE=demo` را در `.env` بگذارید.

## ۹. نسخه اختیاری با مدل زبانی در Dify

فایل `dify/Hakimi_A2A_Optional_LLM_Explainer.yaml` یک نسخه آزمایشی **جدا از ورک‌فلوی قبلی** است که پس از Code یک LLM برای **توضیح متنی محافظه‌کارانه** اضافه می‌کند؛ تصمیم عددی و قیمت‌ها همچنان از موتور Python می‌آیند. در Dify این فایل را به‌عنوان اپلیکیشن جدید Import و در نود LLM، مدلی را که واقعاً در حساب شما فعال است انتخاب کنید. سپس `X-API-Key` را در HTTP Request با ENV محرمانه تنظیم و Workflow را Publish کنید؛ کلید Service API همین اپلیکیشن جدید را در `.env` وارد کنید. این DSL در حساب واقعی Dify شما آزمایش نشده و ممکن است به اصلاح Provider یا Schema نیاز داشته باشد. نسخه پایه بدون LLM برای اتصال پایدارتر پیشنهاد می‌شود.

## تفاوت کلید A2A با کلید API برنامه Dify

این دو کلید متفاوت‌اند و نباید جای یکدیگر استفاده شوند:

1. **کلید A2A:** مقدار `API_KEY` در فایل محلی `.env` است. پس از Import کردن YAML، در Dify Studio از بخش Environment Variables یک متغیر از نوع Secret با نام `A2A_API_KEY` بسازید و مقدار آن را برابر همین کلید قرار دهید. HTTP Request node باید هدر `X-API-Key` را با مقدار `{{#env.A2A_API_KEY#}}` ارسال کند.
2. **کلید Dify:** از مسیر Studio → Access Point → API Key برای برنامه Workflow ساخته می‌شود. این کلید در فایل محلی `.env` با نام `DIFY_API_KEY` قرار می‌گیرد تا داشبورد محلی بتواند Workflow منتشرشده را از طریق API سرویس Dify اجرا کند.

کلید واقعی را در فایل YAML، GitHub، HTML سمت مرورگر یا پیام چت قرار ندهید. فایل‌های YAML این مخزن فقط نام متغیر Secret را تعریف می‌کنند و مقدار واقعی آن باید پس از Import در Dify Studio تنظیم شود.
